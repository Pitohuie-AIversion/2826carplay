# 生产安全规则

本目录保存云环境 `cloud1-d8gtmns36320e045e` 的生产安全规则基线。规则不会随普通云函数上传自动生效，正式发布前需要在云开发控制台逐项配置并真机复核。

## 数据库

在“文档型数据库 → 集合管理 → 权限管理”中，将 `manifest.json` 列出的每个集合切换为自定义安全规则，并粘贴 `database-deny-client.json`。

项目全部数据库读写均通过云函数完成，因此客户端应禁止直接读取和写入。该规则不会限制云函数服务端和云开发控制台。

## 云存储

在“云存储 → 权限设置 → 自定义安全规则”中粘贴 `storage.json`。

- 只允许客户端读取 `vehicle-images/` 下的车辆展示图片。
- 客户端写入与删除统一禁止（`write: false`），管理员也不直接调用客户端存储上传。
- 图片通过 `adminImageUpload` 云函数上传。每次操作根据微信 `OPENID` 校验 `vehicle_manage`、`booking_manage` 或管理员权限，并检查目标车辆/预约及交接阶段；文件路径由服务端生成。
- 单文件实际字节数不能超过 10 MiB，按 192 KiB 分块传输。服务端校验 JPEG、PNG、WebP 的二进制容器结构，拒绝伪装后缀和损坏结构；PNG 另检查 CRC。此校验不等同图片内容审核或完整像素解码。
- 会话与分块位于禁止客户端读写的 `admin_upload_sessions` 集合；上线需创建清单中的 `expiresAt`、`openid + expiresAt` 索引。会话有效 15 分钟，每位管理员最多 9 个未完成会话、每小时最多新建 36 个；车辆图片连同待关联上传最多 9 张，交接同阶段最多 4 个未完成上传。
- 成品上传前即登记 `pending_file_deletions` 延迟引用核验任务，过期会话清理本身不删除成品；车辆与交接资料仍由原业务云函数关联并核验权限、路径、数量。
- 同一请求通过服务端 `request` 记录定位会话，过期清理后重建使用独立随机编号，旧清理或取消无法触及新会话及分块。完成上传的有效租约继续占用名额，不能仅凭会话初始过期时间提前释放；请求映射沿用同集合与现有索引。
- 车辆显式 `cleanupUpload` 仅为事务核验后未引用的成品写入 `uploadAbandoned`，供新请求释放目标占位；自动预登记的待核验任务不释放名额。旧请求返回成品前还会核对删除标记，已进入删除流程的文件不能再次返回。已引用图片与尚在 pending 阶段的迟到关联继续按原引用保护协议处理。

`expiresAt` 是业务过期时间，不会自动删除数据库记录。开始上传时会有界回收当前调用者的过期数据；管理员应定期在“我的 → 存储清理”执行图片任务清理及上传会话清理，每次最多扫描 50 条上传记录，仍有记录时可再次执行。会话记录清理同时移除其分块；清理失败会明确提示，不视为已完成。上线后同时开启存储和数据库容量告警。

## 云函数

在“云函数 → 权限控制”中粘贴 `functions.json`。云函数安全规则只判断 `auth` 是否存在；车辆、预约、隐私、日志等敏感操作继续由云函数根据微信 `OPENID` 和 `roles` 集合在服务端校验。不要在云函数安全规则中访问 `auth.loginType`，该成员只适用于数据库或云存储规则。

## 生效验证

规则修改后等待 1–3 分钟，再执行：

1. 普通用户无法通过调试器直接读取或写入任一数据库集合。
2. 首页和车辆详情仍可展示 `vehicle-images/` 中的图片。
3. 普通用户绕过页面直接调用客户端存储上传仍被拒绝，调用 `adminImageUpload` 的 begin/chunk/complete/abort 也不能取得管理员上传能力；`cleanup` 的 `ownOnly: true` 仅允许回收本人到期记录。
4. 管理员可通过上传代理提交不超过 10 MiB 的车辆或交接图片，并能在对应业务页面关联、设为封面或删除。验证超限、伪装格式、撤权、重复完成及回执丢失重试；10 MiB 文件应分为 54 块。
5. 未登录客户端不能调用云函数；没有有效微信 `OPENID` 的客户端不能执行用户数据或管理类敏感操作，正常微信小程序用户流程不受影响。
