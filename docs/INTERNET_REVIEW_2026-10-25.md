# 爱迦租车：互联网资料对照检视

检视日期：2026-10-25。初始检视代码基准：`9bcc22c`，保留检视开始前已有的 README 修改。以下发现与“已执行与可复用的验证”保留初始检查快照；用户随后要求按检查处理，实施结果见文末“整改记录”。未发布小程序或访问真实云环境。

本次通过公开互联网检索微信、腾讯 CloudBase、Node.js 和 W3C 的一手资料，并对照本地代码。公开名称检索未找到能可靠对应本项目账号的入口，因此以下结论属于代码与平台契约检查，不代表已经体验线上小程序。微信文档部分页面无法经网页工具读取，交叉使用直接 HTTPS 读取与微信官方 `api-typings`。

## 优先处理的发现

### 1. 高优先级：云存储写入权限未限定业务管理员

**证据：** `security-rules/storage.json:3` 只检查登录身份、目录、后缀和文件所有者；没有管理员角色或单次上传授权约束。车辆图片在 `pages-admin/vehicle-detail-manage/vehicle-detail-manage.js:943` 由客户端直接上传，之后才调用业务云函数关联车辆。

按仓库规则推断，如果线上采用同一基线，普通微信登录用户也可以创建属于自己的 `vehicle-images/` 或 `handover-images/` 文件，绕过管理页面的入口限制。车辆资料云函数的角色校验仍能阻止未授权修改车辆记录，但无法撤销此前独立完成的存储上传。主要影响是存储和流量消耗、未关联文件残留；本次没有证据表明用户能覆盖他人文件或读取私有交接照片。

**离线验证：** 用本地规则表达式求值，给定普通微信身份、同一文件创建者，以及两个允许目录中的新 `.jpg` 路径，结果均为 `true`。输入大小为 11 MiB 也不影响结果。此验证只证明表达式行为，不代替 CloudBase 在线鉴权验证；未上传测试文件。

10 MB 限制目前由客户端落实，规则自身没有大小检查，但 `security-rules/README.md:17` 仍称单文件不能超过 10 MB。`__tests__/securityRules.test.js:71` 明确说明上传授权阶段的 `resource.size` 不可靠，故不能直接补一个该字段判断作为修复。

**建议：** 在服务端校验业务角色后授予受限的上传能力，限定路径、时效、数量和配额，并验证实际文件大小与内容；同步文档与测试口径。现有删除任务读取待清理队列，不能保证发现绕过业务链路且从未入队的上传。

**官方依据：** CloudBase 安全规则作用于客户端文件请求，文件所有者条件不等于项目业务角色；服务端 SDK 的权限边界独立。[云存储安全规则](https://docs.cloudbase.net/storage/security-rules)

### 2. 中优先级：CSV 预览超出微信文档接口支持范围

**证据：** 以下调用明确传入 `fileType: "csv"`：

- `shared/csvFile.js:118`
- `pages/booking-manage/booking-manage.js:679`
- `pages/booking-detail/booking-detail.js:1307`
- `pages/booking-manage-detail/booking-manage-detail.js:1287`

官方 `OpenDocumentOption` 的格式枚举不包含 CSV。影响预约导出、交接单，以及复用共享方法的审计日志、错误日志、隐私台账；部分分享失败后的“打开查看”回退也依赖同一接口。属于明确的接口契约不匹配，不能保证不同微信版本成功预览；本次未做真机失败率测试。

**建议：** CSV 保留文件分享能力，预览直接展示已有数据；如需要系统文档预览，则生成真实 PDF/XLSX。不要仅修改后缀。交互仿真 `scripts/simulateAllComponentClicks.js:172` 的 `openDocument` 桩直接回调成功，未验证格式，因此已有点击测试通过不能排除此问题。

**官方依据：** [微信官方 OpenDocumentOption 定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts#L9251-L9276)。

### 3. 中优先级：相册授权拒绝后缺少页面内恢复入口

**证据：** `pages/car-detail/car-detail.js:1732`、`pages/favorites/favorites.js:836` 将授权失败归为“请开启相册权限”，没有检查授权状态或提供设置入口。

微信说明用户拒绝权限后，再次调用同一能力不会重新弹出授权询问。用户重新点保存海报会继续看到提示，需要自行寻找设置。当前失败分支还将包含 `auth` 的错误笼统归为相册权限，未区分隐私同意与系统权限。

**建议：** 提供用户主动点击的设置入口，返回后重新检查 `scope.writePhotosAlbum`，再由用户重试；隐私同意失败使用对应处理，不循环自动弹窗。继续保留原生动作的页面生命周期守卫。

**官方依据：** [微信授权机制](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/authorize.html)。

### 5. 中优先级：关键业务提示的文字对比度不足

**证据：** `pages/booking/booking.wxml:429` 的“提交预约不产生费用，最终安排以顾问确认为准”使用 `pages/booking/booking.wxss:199` 的 `#59626e`，字号为 `18rpx`。按页面底部背景 `#0b0d10` 计算，对比度约 **3.15:1**。车库列表末尾提示 `pages/garage/garage.wxss:69` 的 `#586373` 对同一背景约 **3.19:1**。

两处均低于 WCAG 普通文字 4.5:1 的参考标准。这里采用该标准作为可读性基准，不将其等同微信强制审核条件；数值来自样式静态计算，没有替代真机截图、系统字体设置和视觉验收。

**建议：** 优先提高业务提示与正文的前景亮度，并在窄屏及系统大字体下检查换行、截断和阅读距离；不要仅以字号声明的最小值证明可读性。

**官方依据：** [W3C 文字最低对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)。
